title: "Custom metrics"

These routes start with `/api/public`. [Get an API key](/reference/api-keys), read [Authorization](/reference/api-authorization), and use [Ad accounts](/reference/ad-accounts-api) to find `ad_account_id` before you start. The examples use sample UUIDs. Replace them with your own IDs. Each curl block has a copy control.

## List metrics

`GET /api/public/custom-metrics`

Set the required `ad_account_id`. You can filter by `query`, `status` (`active`, `archived`, or `all`), or `entity_level`. Use `limit` (1–100, default 50) and `cursor` for more pages.

**Request**

```bash
curl --request GET 'https://api.superlaunch.pro/api/public/custom-metrics?ad_account_id=10000000-0000-4000-8000-000000000001&status=active&limit=50' \
  --header "Authorization: Bearer $SUPERLAUNCH_API_KEY"
```

**Response — HTTP 200**

```json
{
  "items": [
    {
      "id": "20000000-0000-4000-8000-000000000001",
      "ad_account_id": "10000000-0000-4000-8000-000000000001",
      "key": "crm_purchases",
      "label": "CRM purchases",
      "description": "Daily purchases from CRM",
      "supported_input_levels": [
        "campaign"
      ],
      "value_type": "integer",
      "unit": "count",
      "allow_negative": false,
      "status": "active",
      "updated_at": "2026-10-24T10:00:00Z"
    }
  ],
  "next_cursor": null,
  "complete": true
}
```

Keep the account and filters the same when you use `next_cursor`.

## Create a metric

`POST /api/public/custom-metrics`

Send a unique `Idempotency-Key` header and the metric definition. The account UUID comes from [Ad accounts](/reference/ad-accounts-api).

**Request**

```bash
curl --request POST 'https://api.superlaunch.pro/api/public/custom-metrics' \
  --header "Authorization: Bearer $SUPERLAUNCH_API_KEY" \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: crm-purchases-definition-1' \
  --data '{
  "ad_account_id": "10000000-0000-4000-8000-000000000001",
  "key": "crm_purchases",
  "label": "CRM purchases",
  "description": "Daily purchases from CRM",
  "supported_input_levels": [
    "campaign"
  ],
  "value_type": "integer",
  "unit": "count",
  "allow_negative": false
}'
```

**Response — HTTP 201**

```json
{
  "id": "20000000-0000-4000-8000-000000000001",
  "ad_account_id": "10000000-0000-4000-8000-000000000001",
  "key": "crm_purchases",
  "label": "CRM purchases",
  "description": "Daily purchases from CRM",
  "supported_input_levels": [
    "campaign"
  ],
  "value_type": "integer",
  "unit": "count",
  "allow_negative": false,
  "status": "active",
  "updated_at": "2026-10-24T10:00:00Z"
}
```

A replay with the same key and payload returns the same definition. A different payload with that key returns HTTP 409.

## Edit a metric

`PATCH /api/public/custom-metrics/{metric_id}`

Send `ad_account_id` and the last `updated_at` from a read. This prevents an edit from overwriting a newer definition. You can change the label, description, input levels, or status.

**Request**

```bash
curl --request PATCH 'https://api.superlaunch.pro/api/public/custom-metrics/20000000-0000-4000-8000-000000000001' \
  --header "Authorization: Bearer $SUPERLAUNCH_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{
  "ad_account_id": "10000000-0000-4000-8000-000000000001",
  "updated_at": "2026-10-24T10:00:00Z",
  "label": "CRM purchases (verified)"
}'
```

**Response — HTTP 200**

```json
{
  "id": "20000000-0000-4000-8000-000000000001",
  "ad_account_id": "10000000-0000-4000-8000-000000000001",
  "key": "crm_purchases",
  "label": "CRM purchases (verified)",
  "description": "Daily purchases from CRM",
  "supported_input_levels": [
    "campaign"
  ],
  "value_type": "integer",
  "unit": "count",
  "allow_negative": false,
  "status": "active",
  "updated_at": "2026-10-24T11:00:00Z"
}
```

A stale `updated_at` returns a conflict. Read the metric again before you retry.

## Download the CSV template

`GET /api/public/custom-metrics/template.csv`

Set `ad_account_id`. This route returns the current CSV format and metric keys for that account. Save the response as a file before you prepare a CSV import.

**Request**

```bash
curl --request GET 'https://api.superlaunch.pro/api/public/custom-metrics/template.csv?ad_account_id=10000000-0000-4000-8000-000000000001' \
  --header "Authorization: Bearer $SUPERLAUNCH_API_KEY" \
  --output custom-metrics-template.csv
```

**Response — HTTP 200**

```http
Content-Type: text/csv
Content-Disposition: attachment; filename=custom-metrics-template.csv
```

Open the saved file to see its headers. Keep those headers when you add rows.

## Prepare JSON rows

`POST /api/public/custom-metric-imports`

Send an account UUID, an idempotency key, and up to 1,000 daily rows. `value` is a decimal string. Use a closed date in the account time zone.

**Request**

```bash
curl --request POST 'https://api.superlaunch.pro/api/public/custom-metric-imports' \
  --header "Authorization: Bearer $SUPERLAUNCH_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{
  "ad_account_id": "10000000-0000-4000-8000-000000000001",
  "idempotency_key": "crm-export-2026-10-23",
  "rows": [
    {
      "metric_id": "20000000-0000-4000-8000-000000000001",
      "entity_level": "campaign",
      "entity_id": "120000000001",
      "date": "2026-10-23",
      "value": "30"
    }
  ]
}'
```

## Create a CSV upload grant

`POST /api/public/custom-metric-upload-grants`

Use this route if your client cannot send a multipart file. Send the file name, exact byte size, content type, account, and idempotency key.

**Request**

```bash
curl --request POST 'https://api.superlaunch.pro/api/public/custom-metric-upload-grants' \
  --header "Authorization: Bearer $SUPERLAUNCH_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{
  "ad_account_id": "10000000-0000-4000-8000-000000000001",
  "idempotency_key": "crm-upload-2026-10-23",
  "file_name": "custom-metrics.csv",
  "content_type": "text/csv",
  "size_bytes": 256
}'
```

**Response — HTTP 200**

```json
{
  "upload_id": "40000000-0000-4000-8000-000000000001",
  "upload_url": "https://api.superlaunch.pro/api/public/custom-metric-uploads/40000000-0000-4000-8000-000000000001",
  "method": "PUT",
  "authorization": "Bearer <one-time-upload-token>",
  "expires_at": "2026-10-24T10:15:00Z"
}
```

The grant has a short expiry. Keep its `authorization` value out of logs. Use the returned URL and header for the upload.

## Query metric values

`POST /api/public/metrics/query`

Send an account UUID, entity level, metric references, and date range. Use `custom:<metric_uuid>` for a custom metric. `grain` is `daily` or `period`. The response can also include supported provider metrics.

**Request**

```bash
curl --request POST 'https://api.superlaunch.pro/api/public/metrics/query' \
  --header "Authorization: Bearer $SUPERLAUNCH_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{
  "ad_account_id": "10000000-0000-4000-8000-000000000001",
  "entity_level": "campaign",
  "metric_refs": [
    "custom:20000000-0000-4000-8000-000000000001"
  ],
  "date_from": "2026-10-23",
  "date_to": "2026-10-23",
  "grain": "daily"
}'
```

**Response — HTTP 200**

```json
{
  "rows": [
    {
      "ad_account_id": "10000000-0000-4000-8000-000000000001",
      "provider": "meta",
      "provider_account_id": "act_120000000001",
      "entity_level": "campaign",
      "entity_id": "120000000001",
      "entity_name": "Example campaign",
      "date_from": "2026-10-23",
      "date_to": "2026-10-23",
      "timezone": "America/New_York",
      "metrics": [
        {
          "metric_ref": "custom:20000000-0000-4000-8000-000000000001",
          "value": "30",
          "unit": "count",
          "currency": null,
          "quality": "ready",
          "import_ids": [
            "30000000-0000-4000-8000-000000000001"
          ],
          "created_at": "2026-10-24T10:00:00Z",
          "updated_at": "2026-10-24T10:00:00Z"
        }
      ]
    }
  ],
  "definitions": [
    {
      "metric_id": "20000000-0000-4000-8000-000000000001",
      "updated_at": "2026-10-24T10:00:00Z"
    }
  ],
  "next_cursor": null,
  "complete": true
}
```

Use `cursor` and `limit` for more rows. A missing metric value stays null. Reads can include corrections from an active or failed import.
