Before you submit, confirm the workspace, ad account, approved creative versions, and campaign settings. A launch can create campaigns and ads in Meta and count toward your workspace usage.

## Choose an operation

Choose a **Launch type**:

| Launch type | Use it to |
| --- | --- |
| Test new creatives | Create a test from approved library content |
| Promote successful tests | Use results from earlier tests in a new campaign or an existing ad set |
| Refresh an existing ad set | Add creatives to an ad set you select |

For an existing ad set, review its current settings before submitting.

Through MCP, call `launcher_discover`, resolve accounts, and use `launcher_targets_list` followed by `launcher_targets_get` when an existing target is required.

## Prepare the inputs

1. Open **Launcher** and choose the ad account.
2. Select **New launch** and enter a **Launch name**.
3. Select the operation and template version.
4. Choose creatives or resolve a collection.
5. Review grouping, budget, and targeting.
6. Choose the launch time. Recurring timing is available for **Test new creatives**.
7. Choose **Create paused** or **Activate after creation**.

Activation can start delivery and spend. Confirm that choice before submission.

## Preview

Select **Preview (optional)** to check the planned Meta objects, names, estimated usage, and configured budgets. Meta can still reject a request at submission or execution.

Correct missing inputs and review the selection. Submission checks permissions, approval, provider state, billing, and limits again.

## Submit and track

Submit the launch once. Your agent should use one stable `request_key` for the intended operation and retain the returned launch ID.

Read `launcher_launches_get` and `launcher_run_operations` until you understand the final outcome. A batch can contain both successful and failed operations. See [Recover a launch](/launcher/recovery).
