Discover exact provider assets and targets before preparing a launch. Preview reserves nothing. Submission uses one stable request key and returns work to track. Read operation results before retrying; corrected replacement inputs require a new request key.

The parameter tables show the top-level arguments and common nested objects. Expand the input schema for nested formats, constraints, and allowed values.

Successful Launcher responses include `status: "ok"`, the returned object or page, and `next_actions`. Follow returned cursors using the parameter specified by the tool. An accepted launch is not a completed provider write.

## launcher_assets_list

Find named Meta assets without copying IDs from another product. Pages, apps, pixels and audiences use the selected account. Forms, Instagram and catalogs require parent_id=Page ID. Product sets require parent_id=catalog ID plus page_id. Pages and Instagram accounts come from the synced ClickHouse catalog; inspect sync_status and synced_at for freshness. Other assets use live Meta discovery. Follow next_cursor; discovery does not guarantee launch eligibility.

**Access:** `mcp:read`. Object and function permissions also apply.

| --- | --- | --- | --- |
| `ad_account_id` | uuid | Required | See input schema. |
