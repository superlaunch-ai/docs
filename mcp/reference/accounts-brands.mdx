## brands_create

Create a brand in the current workspace and grant its creator write access. Supply a fresh request_id UUID. Reuse it with the same payload to safely retry; changed payloads conflict. Optional profile fields are website, industry, description, markets, and languages. No ad accounts are linked.

**Access:** `mcp:read` and `mcp:write`. Workspace and target permissions also apply.

| Parameter | Type | Required / default |
| --- | --- | --- |
| `payload` | object | Required |

Keep the argument nesting shown in the schema. Expand it for nested fields, allowed values, and limits.

<Accordion title="Full input schema">

```json
{
  "additionalProperties": false,
  "properties": {
    "payload": {
      "additionalProperties": false,
      "description": "Create a workspace brand; reuse request_id only for identical retries.",
      "properties": {
        "request_id": {
          "format": "uuid",
          "type": "string"
        },
        "name": {
          "maxLength": 200,
          "minLength": 1,
          "pattern": "\\S",
          "type": "string"
        },
        "website": {
          "anyOf": [
            {
              "maxLength": 500,
              "type": "string"
            },
            {
              "type": "null"
            }
          ],
          "default": null
        },
        "industry": {
          "anyOf": [
            {
              "maxLength": 200,
              "type": "string"
            },
            {
              "type": "null"
            }
          ],
          "default": null
        },
        "description": {
          "anyOf": [
            {
              "maxLength": 10000,

            },
            {
              "type": "null"
            }
          ],
          "default": null
        },
        "markets": {
          "items": {
            "maxLength": 100,

          "maxItems": 50,

          "items": {
            "maxLength": 100,

            "pattern": "\\S",

          "maxItems": 50,
          "type": "array"
```

## brands_update

Update mutable fields on one writable brand. Supply a fresh request_id UUID and at least one field. Reuse the request_id with the same brand and payload to safely retry; changed payloads conflict. Empty markets or languages clear those lists. Use kit to partially update messaging, voice, colors, or typography; a changed kit creates an immutable version. kit.positioning is required when no active kit exists.

**Access:** `mcp:read` and `mcp:write`. Workspace and target permissions also apply.
